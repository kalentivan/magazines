# UX и структура

Главная: оффер → пример → поводы → авторский процесс → бюджет → отели → FAQ → заявка.
Отели: оффер → лобби/подарок/продажа → содержание → этапы пилота → живопись → B2B-заявка.
Другие пути: world/dreams/art и старые редиректы, privacy для журналов, неизменённая policy для ABIE, legacy со старой главной.

## Сценарии

B2C: понять продукт → полистать → оценить процесс/бюджет → оставить имя и контакт, по желанию дату/идею → получить ID сохранённой заявки → менеджер читает запись, связывается и отмечает обработанной.
B2B: открыть hotels → выбрать сценарий мысленно → увидеть этапы пилота → указать отель, контакт, задачу, необязательный тираж → тот же API с lead_type=b2b.

## Wireframes

Desktop: header одной строкой; hero текст слева / цифровые страницы справа; примеры в двух колонках; процесс и FAQ — заголовок слева, детали справа; контакт — пояснение слева, форма справа.
Mobile: одна колонка в порядке чтения; меню раскрывается кнопкой; CTA до примера; все поля формы в одной колонке; крупные ссылки и кнопки, без модалок для основной заявки.

## Состояния формы

- Конфигурация не готова: fieldset disabled, явное сообщение и отдельный email-контакт; никакого успеха или отправки.
- Готова: обязательные поля и согласие, contact проверяет email/телефон.
- Отправка: кнопка disabled, aria-busy, status «Сохраняем…».
- Успех только после HTTP 2xx + saved=true + lead_id; поля очищаются.
- Сеть/HTTP/невалидный ответ: данные остаются, retry с прежним UUID для неизменной заявки.
- Изменённая заявка: новый UUID; ID-конфликт на сервере возвращает 409.
- Лимит: понятное сообщение о повторе позже.

Согласие на маркетинговую рассылку не запрашивается. Контакты не попадают в URL, localStorage или аналитику.
