# Решения и ограничения

1. Сохраняем статический стек и GitHub Pages. Новый SPA-фреймворк не нужен для двух лендингов; страницы и CTA работают без тяжёлого JS.
2. Главная B2C, отдельная hotels B2B — по ТЗ. Старую главную сохраняем legacy.html; другие страницы и все архивы сохраняются.
3. Отдельный Python 3.12 API + SQLite на существующем сервере — готовый вариант без подписки. Сервер/HTTPS/домен ещё не предоставлены; ничего платного не приобреталось.
4. API возвращает успех только после транзакции SQLite. UUID обеспечивает дедупликацию повторной отправки. Никаких публичных endpoint чтения лидов.
5. Доступ менеджера: SSH + manage.py. Отдельный retry-worker уведомлений через согласованный HTTPS webhook: передаётся ID/тип, не контакт/текст. Запуск и канал владельцем пока не настроены.
6. Production config оставлен endpoint пустым и privacyApproved=false. Политика ABIE сохранена; новая privacy — честное уведомление о текущем статусе, не выдуманный утверждённый юридический документ.
7. Тестовый receiver включается только флагом локального preview; принимает только синтетические QA данные. Он не является production-хранилищем.
8. Аналитика — локальный интерфейс событий без сетевой отправки. Провайдер и согласие не выбраны, поэтому статистика посещений не собирается.
9. Цена и сроки — по согласованию. Отзывы, клиенты, физические фото и измеренные конверсии не выдумывались.
10. Backend в примере за reverse proxy имеет консервативный общий лимит по адресу proxy. Перед масштабированием добавить доверенную обработку IP на edge и защиту от распределённого спама. CORS не является аутентификацией.
11. Текущий выпуск — обновление витрины с проверенным локальным приёмом; коммерческий запуск lead capture заблокирован до доступа/политики/production smoke test.
